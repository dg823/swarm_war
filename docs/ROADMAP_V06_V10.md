# SWARM WAR V0.6 ~ V1.0 개발 요구사항 (사용자 원문)

> 사용자가 2026-11-10에 준 장기 개발 프롬프트를 그대로 보관한 것이다. 설계 결정과 진행 상황은 `HANDOFF.md`를 본다.

## 1. 프로젝트 목표
기존 Processing 기반 프로젝트인 SWARM WAR를 발전시킨다.
현재 V0.5까지 구현되어 있으며, Boids 군집 알고리즘, 공간 분할, 전투 AI, 생태계, 유전 알고리즘, 플레이어 지휘 시스템과 UI가 존재한다.
앞으로의 개발 방향은 대규모 전술 전쟁 시뮬레이션이다.
단순히 서로 다른 종족이 상성에 따라 싸우는 게임이 아니라, 수천 개의 개체가 군대처럼 움직이며 진형을 형성하고, 측면 공격과 포위, 돌파, 후퇴 등의 전술을 수행하는 전장을 구현한다.
가장 중요한 목표는 기능의 개수가 아니라 전투 장면의 시각적 완성도와 전쟁의 규모감이다.

## 2. 반드시 지켜야 할 개발 원칙
- 기존 코드를 먼저 분석하고 현재 구조를 최대한 유지한다.
- 기존에 구현된 기능을 임의로 삭제하거나 단순화하지 않는다.
- Processing 환경에서 실제 구현 가능한 수준으로 설계한다.
- 불필요하게 복잡한 알고리즘이나 과도한 추상화를 피한다.
- 수천 개의 개체가 동시에 움직이는 상황을 고려한다.
- 개체마다 무거운 연산을 반복하지 말고 군집 단위로 처리한다.
- 객체 풀과 기존 SpatialGrid를 적극적으로 재사용한다.
- 기존 시드 재현성과 SelfTest 구조를 유지한다.
- 시뮬레이션 로직과 렌더링 로직을 분리한다.
- 새로운 기능을 추가할 때 기존 기능의 정상 작동 여부를 확인한다.
- 구현하지 않은 기능을 구현 완료했다고 표시하지 않는다.

## 3. 개발 로드맵

### V0.6 - Formation System
군집이 실제 군대처럼 진형을 형성하고 이동하도록 구현한다.
- LINE: 일자형 진형 / WEDGE: 쐐기형 진형 / CIRCLE: 원형 진형 / COLUMN: 종대 진형 / SCATTER: 산개 진형
- 군집 중심과 진행 방향을 기준으로 진형 구성
- 진형 전환 및 유지
- 이동 중 자연스러운 대형 변화
- 장애물 회피
- 적과 교전할 때 진형이 자연스럽게 무너지고 재정비되는 동작

개체를 고정된 위치에 강제로 배치하지 말고, Boids 알고리즘과 결합해 자연스러운 움직임을 구현한다.

### V0.7 - Tactical Warfare AI
군집이 상황을 분석하고 전술적으로 행동하도록 구현한다.
- 전선 분석, 아군과 적군의 지역별 병력 집계, 적의 약한 지역 탐지
- 측면 공격, 집중 공격, 포위 전술, 전선 돌파
- 불리한 상황에서 후퇴, 후퇴한 군집의 재집결
- 목표 지역 점령 및 방어

AI 계층:
1. Strategic AI: 전쟁 전체의 목표 결정
2. Tactical AI: 포위, 돌파, 측면 공격 등의 전술 결정
3. Squad AI: 군집 이동과 진형 관리
4. Agent AI: 개체의 회피, 공격, 생존 행동

전술 판단은 매 프레임 실행하지 않고 일정 주기로 처리한다. 개체의 기본 움직임은 기존 Boids 시스템을 활용한다.

### V0.8 - Battlefield Effects
- 투사체와 발사 효과, 피격 효과, 폭발 및 충격파, 개체 사망 효과, 에너지 잔상
- 전투 중 발생하는 연기와 파편
- 공격 방향과 피해 상황을 알 수 있는 시각적 표현
- 종족별 차별화된 전투 이펙트

효과는 객체 풀을 사용해 관리하고, 과도한 파티클 생성으로 성능이 저하되지 않도록 제한한다.

### V0.9 - War Presentation
- 전장을 따라가는 카메라, 확대 및 축소, 미니맵
- 현재 전선 표시, 종족별 생존 개체 수, 지역별 병력 밀도, 점령 지역 표시
- 전투 통계 HUD, 주요 전투 상황을 강조하는 카메라 연출

전투가 진행되는 동안 플레이어가 전장의 흐름을 한눈에 이해할 수 있어야 한다.

### V1.0 - Final Warfare
- 정복전, 전멸전, 생존전, 지역 점령전, 샌드박스 모드
- 개체 수와 전투 규모 설정, 종족별 전투 특성 조정
- 렌더링 최적화, 장시간 실행 안정성 검증, 최종 UI 및 게임 밸런스 조정

## 4. 시각적 방향
- 어두운 SF 전장: 어두운 배경과 단순한 지형, 종족별로 명확히 구분되는 색상
- 개체의 움직임이 잘 보이는 형태, 공격과 피격을 구분할 수 있는 이펙트
- 대규모 군집이 움직일 때 느껴지는 밀도감, 전투가 진행될수록 변화하는 전장 분위기

화려함이 아니라 **전술적 행동이 시각적으로 드러나야** 한다. 포위가 진행되면 실제로 적군의 양쪽을 감싸는 모습이 보여야 하고, 돌파 명령을 내리면 군집이 한 방향으로 집중되어 전선을 밀어내는 모습이 보여야 한다.

개체 수에 따른 렌더링 수준:
- 확대: 개체의 형태와 세부 움직임 표시
- 기본 배율: 단순화된 개체 표시
- 축소: 군집의 밀도와 전체 이동 방향 중심

## 5. 성능 및 기술적 제한
- 고정 타임스텝 1/60초, 기존 SpatialGrid 재사용
- 군집 대표 개체 중심의 경로 탐색, Flow Field 등 공유 경로 정보 활용
- 전술 판단은 5~10Hz 수준으로 제한
- 투사체와 파티클 객체 풀 사용
- 렌더링과 시뮬레이션 시간 별도 측정
- 불필요한 객체 생성 최소화, 화면 밖 개체의 렌더링 비용 절감

모든 기능을 무조건 구현하지 말고, 실제 성능을 측정하면서 개발한다.

## 6. 작업 진행 방식
개발을 시작하기 전에 현재 프로젝트 전체를 분석한다: ① 기존 클래스와 시스템의 역할 ② 현재 V0.5 구현 상태 ③ 이미 구현된 기능과 중복되는 기능 ④ 현재 성능 병목 가능성 ⑤ 새 기능을 추가할 때 수정해야 하는 클래스 ⑥ 기존 테스트와 검증 방법.

그다음 V0.6부터 순서대로 진행한다. 각 버전은 다음 과정을 따른다.
1. 구현 목표와 설계 정리 2. 수정할 파일과 추가할 파일 결정 3. 실제 코드 구현 4. 기존 기능과의 호환성 확인
5. SelfTest 및 신규 테스트 수행 6. 성능 측정 7. 문제 수정 8. 완료된 기능과 미완성 기능 정리

한 번에 모든 버전을 구현하지 않는다. 각 버전을 독립적으로 검증한 후 다음 버전으로 넘어간다.

## 7. 최종 목표
수천 개의 개체가 하나의 전장에서 서로 다른 전술을 수행하는 대규모 전쟁 시뮬레이션. 플레이어는 개체를 직접 조종하지 않고 군집에 명령을 내리며, 군집은 자율적으로 움직이며 전술을 수행한다.
- 수백 마리의 군집이 일제히 진격하는 장면
- 적의 측면을 돌아 포위하는 장면
- 여러 군집이 한 지점에 집중 공격하는 장면
- 전선이 무너지고 적군이 후퇴하는 장면
- 흩어진 군집이 다시 진형을 갖추는 장면
- 수천 개체가 동시에 교전하는 대규모 전투 장면

가장 중요한 것은 실제 전쟁처럼 보이는 움직임이다. 기존 프로젝트를 무리하게 갈아엎지 말고, 이미 완성된 기반 위에 단계적으로 발전시켜라.
